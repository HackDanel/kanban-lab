# BUG-014

**Заголовок:** Нулевой символ во входных данных вызывает ошибку 500

**Окружение:** GitHub Actions, OWASP ZAP (API scan по OpenAPI), стек Docker Compose

**Чем найден:** активное сканирование API OWASP ZAP (`tests/security/zap-baseline.sh`)

**Шаги:**

1. Войти, получить access-токен.
2. Выполнить `GET /api/v1/users?q=%27%22%00%3CscrIpt%3Ealert%281%29%3B%3C%2FscRipt%3E`.

**Ожидаемый результат:** `400 VALIDATION_ERROR`.

**Фактический результат:** `500 INTERNAL`: PostgreSQL не допускает символ NUL в тексте и отвергает запрос целиком. Та же ошибка возникала при NUL в поиске по карточкам, в email при входе и в любом текстовом поле JSON (`\u0000`).

**Severity:** Major

**Priority:** Medium

**Вложение:** отчёт `zap-api.html` из артефактов сборки, алерт «A Server Error response code was returned by the server»

**Статус:** исправлен — middleware `rejectNUL` отвечает 400 на NUL в адресе и JSON-теле (`backend/internal/http/middleware.go`); тест `TestNULCharactersAreRejected`.
