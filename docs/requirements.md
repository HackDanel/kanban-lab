# Анализ требований

Источник — методические указания к лабораторной работе № 16 «Разработка Kanban-доски и полноценное тестирование ПО». Каждому требованию присвоен идентификатор, по которому оно прослеживается до эндпоинтов API и тест-кейсов.

## Функциональные требования

| ID | Требование | Реализация (API) | Тест-кейсы |
|---|---|---|---|
| FR-01 | Регистрация | `POST /auth/register` | TC-01 |
| FR-02 | Вход, выход, JWT | `POST /auth/login`, `/auth/refresh`, `/auth/logout`, `GET /auth/me` | TC-01, E2E-01 |
| FR-03 | Роли: администратор, менеджер, разработчик | `PUT /users/{id}/role`, middleware ролей | TC-04, E2E-02 |
| FR-04 | Проекты: создание, редактирование, удаление, список | `/projects`, `/projects/{id}` | TC-04, E2E-01 |
| FR-05 | Участники проекта | `/projects/{id}/members` | E2E-02 |
| FR-06 | Доски в рамках проекта | `/projects/{id}/boards`, `/boards/{id}` | E2E-01 |
| FR-07 | Колонки: создание, переименование, удаление | `POST /boards/{id}/columns`, `PATCH`/`DELETE /columns/{id}` | E2E-01 |
| FR-08 | Колонки: изменение порядка | `POST /columns/{id}/move` | — |
| FR-09 | WIP-лимиты | поле `wipLimit`, ответ `409 WIP_LIMIT_EXCEEDED` | TC-07 |
| FR-10 | Карточки: создание, редактирование, удаление | `POST /columns/{id}/cards`, `/cards/{id}` | TC-02, TC-05 |
| FR-11 | Перемещение карточек drag-and-drop | `POST /cards/{id}/move` | TC-03, TC-07 |
| FR-12 | Исполнитель, приоритет, дедлайн, описание | поля карточки | TC-02 |
| FR-13 | Метки | `/projects/{id}/labels`, `/labels/{id}`, поле `labelIds` | TC-06 |
| FR-14 | Комментарии | `/cards/{id}/comments`, `/comments/{id}` | — |
| FR-15 | Вложения | `/cards/{id}/attachments`, `/attachments/{id}` | — |
| FR-16 | Фильтрация и поиск по тексту, исполнителю, меткам, приоритету | `GET /boards/{id}/cards` с параметрами `q`, `assigneeId`, `labelId`, `priority` | TC-06 |
| FR-17 | История действий по задаче | `GET /cards/{id}/activity` | — |
| FR-18 | Разграничение прав по ролям | middleware и проверки в сервисах | TC-04, E2E-02 |
| FR-19 | Обновление доски в реальном времени (опционально) | `GET /ws` | — |

Вне объёма работы: уведомления (email и in-app) и восстановление пароля. Методические указания относят уведомления к опциональным; TC-08 «Восстановление пароля» в тест-плане отмечен как неприменимый.

Прочерк в столбце тест-кейсов означает, что требование покрывается интеграционными и API-тестами; идентификаторы добавляются по мере написания тестов.

## Нефункциональные требования

| ID | Требование | Как обеспечивается | Как проверяется |
|---|---|---|---|
| NFR-01 | Отклик API < 200 мс при 1000 одновременных пользователях | пул соединений pgx, индексы, кэш Redis, пагинация | k6, порог `p(95) < 200` |
| NFR-02 | Поддержка 10 000 карточек | индексы `pg_trgm` и btree, постраничная выдача | k6 на засеянной базе |
| NFR-03 | Защита от XSS | текст без HTML, экранирование React, CSP | ZAP, E2E с вредоносным вводом |
| NFR-04 | Защита от CSRF | Bearer-токен в заголовке, double-submit для refresh | интеграционные тесты, ZAP |
| NFR-05 | Защита от SQL-инъекций | параметризованные запросы sqlc | интеграционные тесты, ZAP API scan |
| NFR-06 | Хеширование паролей bcrypt | `golang.org/x/crypto/bcrypt`, cost 12 | модульный тест |
| NFR-07 | HTTPS | Nginx + Let's Encrypt, HSTS | проверка staging |
| NFR-08 | Валидация входных данных | схема OpenAPI и валидатор DTO | интеграционные тесты на `400` |
| NFR-09 | Доступность 99,9 %, автовосстановление | healthcheck, `restart: unless-stopped`, graceful shutdown | остановка контейнера на staging |
| NFR-10 | Адаптивный интуитивный интерфейс | MUI, брейкпоинты | юзабилити-чек-лист |
| NFR-11 | Chrome, Firefox, Edge | — | Playwright в трёх браузерах |
| NFR-12 | Покрытие ≥ 80 % строк и ≥ 70 % ветвей | пороги в CI | отчёты покрытия, Codecov |

## Роли и права

| Действие | Администратор | Менеджер | Разработчик |
|---|---|---|---|
| Управление пользователями и ролями | да | нет | нет |
| Создание проекта | да | да | нет |
| Изменение и удаление проекта, управление участниками | да | только свои проекты | нет |
| Доски, колонки, WIP-лимиты, метки | да | в проектах, где участник | нет |
| Просмотр проекта и доски | да | участник проекта | участник проекта |
| Карточки, перемещение, комментарии, вложения | да | участник проекта | участник проекта |
| Изменение чужого комментария | нет | нет | нет |
| Удаление чужого комментария или вложения | да | да | нет |

Новый пользователь получает роль разработчика. Первый администратор создаётся при запуске сервера из переменных окружения.
